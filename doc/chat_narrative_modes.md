# 聚焦与推进模式

## 已确认行为

- 会话默认聚焦，选择独立保存。输入框旁依次为图片、切模式、全屏编辑三个28dp紧凑按钮，合计84dp；发送按钮前间距从8dp缩为4dp，输入框可用宽度保持。全屏输入的图片与模式按钮同样紧凑排列；点击模式不会发送消息。
- 模式组合图标为无外框、无阴影的24×24dp正方形，上方快进箭头代表推进，下方取景框代表聚焦，两枚符号紧贴中间斜线。当前模式图标14dp、另一枚10dp，切换时同步缩放；切到聚焦时斜线上移，切到推进时下移。
- 长按显示当前模式对应的完整系统提示词，直接使用 `PromptTemplates.narrativeModeSystemPrompt`，支持滚动阅读和选择复制。
- 当前用户维护的聚焦提示词采用实时对戏：细写当下动作、对白与心理，只呈现即时反应后等待玩家，不主动快进剧情或总结事件结果。
- 当前用户维护的推进提示词采用事件快进与行动结算：概括已表达意图的合理过程，完成当前事件后给出结果；途中出现必须由玩家拍板的重大意外时停在发生处，不替玩家作新立场选择或承诺。
- 两种模式共用回复字数、语言、格式卡与分段协议。
- 生成中切换仅影响下次发送、继续或重生成。当前回复与中断草稿保存触发时模式；重生成使用新选择，各候选分别保存原模式。

## 实现入口

- `ChatNarrativeMode`、`ChatSession.narrativeMode`、`SaveSlot.narrativeMode` 默认 FOCUS；旧助手消息及无模式元数据的旧候选同样视为 FOCUS。
- `MessageAlternativeVersionPolicy` 将正文、版本身份和 `alternativeNarrativeModes` 一起追加、裁剪、切换；编辑与格式修复保留模式。
- `ChatViewModel` 将选择状态与请求快照分开，切换写入在 Main 调度下串行执行，并在离开页面后继续。保存失败回退到已持久化模式，界面显示原因。
- `ChatNarrativeModeToggle` 直接放入输入框旁的按钮组，不使用Popup。原图片预览右侧、全屏编辑底部及跳到底部按钮的悬浮避让已撤回。全屏编辑通过确认按钮前的行内 `confirmAccessory` 复用同一组件。`CbIconButton.iconSize` 可单独调整内部图形，其他调用默认仍为20dp。生成中切换以短提示说明本次/下次，完整说明也包含该状态；保存失败用 Toast 呈现。
- `ChatRepository.setNarrativeMode` 在会话设置锁内读取最新会话后修改单字段；普通 `updateSession` 保留最新模式，存档恢复和回滚显式覆盖。创建/恢复存档等待当前切换保存完成。
- `PromptTemplates` 的 `FOCUS_NARRATIVE_MODE_SYSTEM_PROMPT`、`ADVANCE_NARRATIVE_MODE_SYSTEM_PROMPT`、`narrativeModeSystemPrompt`、`narrativeModeTailSystemPrompt`、`narrativeModeHistoryReply` 集中维护模型可见规则。发布保留用户对两套模式提示词的最新本地调整，其他既有提示词原文保持。
- 当前模式位于玩家设定之后、上下文确认之前，并参与稳定前缀缓存键；强后置位于格式卡强提示之后、CCB助手确认之前。
- 直接历史的助手正文经过裁剪及占位符渲染后按所选候选模式包装。完整上一轮仍保留全部原文。用户历史、RAG、HEAD、Archive不加模式包装，消息存储和轮次分组不改变。

## 手动验收

准备：配置可用对话模型及角色卡，设置相同回复字数，建立做饭场景。以下属于待人工验证的真实模型行为。

1. 检查输入框旁三个按钮顺序为图片、模式、全屏编辑，输入框宽度和输入栏高度保持；模式图标方形且两枚符号贴近斜线。旧会话和新会话初始为聚焦：下方取景框大、上方快进箭头小。点击切推进，检查快进箭头变大、取景框变小、斜线下移；切回时反向变化。离开重进保留选择，其他会话独立。已有输入、图片和光标不丢失，键盘及全屏输入仍可用。
2. 两种模式下分别长按模式按钮，检查弹窗标题与模式一致，正文为对应完整系统提示词；可滚动读至末尾。长按不切换模式，关闭后按钮组不跳动，正常发送。
3. 聚焦发送“我去做饭”，检查现场互动有动作、对白和心理细节。切推进重生成，检查过程被概括到饭菜完成或实际需要决定的情况，保留角色反应；不得顺带替玩家接受邀请或新增承诺。
4. 在生成中切模式，检查“本次／下次”短提示，长按说明也显示当前/下次状态；当前回复继续，下一次发送或空输入继续采用新选择。中途停止后重进，草稿仍归属开始时模式。
5. 在不同模式下重生成同一条回复，来回切候选，再发送下一条。调试请求中，历史模式对应所选候选；切换强化说明参考被替换版本或最近剧情回复。
6. 调试请求核对完整模式规则在前、模式强后置在格式卡强提示之后、最后仍为助手确认。格式要求 START/END/BOTH 三种位置均保留此顺序；HTTP或实验传输按原协议适配。历史标签只在直接助手历史出现。
7. 推进模式创建存档，切聚焦后读档，应恢复推进。导出导入、复制会话后检查当前模式与候选模式保留；旧存档恢复聚焦。邻近检查：回复字数、姓名标记、状态区块、格式修复、图片、RAG和长期记忆继续正常。
