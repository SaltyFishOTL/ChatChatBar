name: chatbar-character-card-transfer
description: Maintain character PNG export, independent export cover, package transfer and preset dependency restoration.
---

- ManageScreen.CharacterPngExportDialog selects an export-only local image via OpenDocument, previews/crops it through CharacterCardPngExportOptions.coverImagePath, and resets selection for each export. The persisted card background and embedded card package remain original.
- CharacterCardPngRenderer bounds-decodes source images before downsampling; an explicitly chosen unreadable image fails visibly. CharacterCardTransferService retains packaged character assets and optional defaultImageGenerationSettings.
- PresetCatalogService.characterPackage delegates to PresetCharacterDependencies: combine embedded world books with manifest worldBookPresetKeys; embedded defaultFormatCard wins, otherwise resolve optional defaultFormatPresetKey. Missing declared manifest dependencies fail before import. Never invent a default format for an unbound preset.
- CharacterCardTransferService imports dependency resources and binds resulting IDs. WorldBookReusePolicy reuses preset identity; FormatCardTransferService.importCharacterDefault reuses matching sourcePresetKey without replacing local edits, otherwise reuses equal content or imports a separate card.
- Synthetic tests: PresetCharacterDependenciesTest, FormatCardTransferServiceTest, CharacterCardPngRendererInstrumentedTest.

- Multi-background gallery: CharacterCard.chatBackgroundImages and PackagedCharacterCard.chatBackgroundImageResourceIds retain original image assets in package v10. chatBackground remains the default; conversation overrides choose from the gallery without changing the card. Draft materialization reuses one copied path for shared default/gallery assets. CharacterBackgroundRetention excludes only the formal card being cleaned; same-card drafts still retain originals during overwrite/delete, including orphan-draft recovery. Editor save removes its consumed draft before scanning remaining references, so removed gallery images can be reclaimed. Conversation and streaming SaveSlot-summary references also retain originals. Regression: CharacterBackgroundGalleryTransferTest and CharacterDraftDiscardTest.

- CharacterInfo/PackagedCharacter.enabled is the portable card-level gate (legacy Desktop desktopEnabled is a read alias). ChatSession.characterParticipation stores per-card manual choices (legacy desktopCharacterParticipation read alias); SessionCharacterParticipationPolicy is adapted from the neutral Desktop policy. Request-only filtering leaves formal cards/history intact; old automatic pause state is retained and manually controllable, while Android automatic residency production remains separate/pending.

- Retained CharacterEditViewModel observes EditorDraftRepository.drafts: external management-list deletion of its loaded/pending draft resets to the latest formal card and cancels pending autosave, using the same discard path. WorldBookEditViewModel follows the same rule; internal save/discard suppresses observer reset while saving/not ready. ManagementDraftDiscardTest covers existing/new editors, pending restore prompts, no recreation and unrelated-draft isolation.

- A running reply freezes its request-side people view. Its later world-book timing write uses ChatRepository.updateSessionWorldBookClock to patch only the latest clock under the settings mutex, preserving subsequent quick people choices/settings and rejecting a different bound card.

- Ordinary ChatRepository.updateSession snapshot writes also preserve the latest participation/auto-pause fields, like the existing narrative-mode protection. The existing explicit save-slot restoration flag restores stored choices; first writes retain supplied initial choices. Dedicated quick toggles and settings-draft saves remain the mutation paths.

- CharacterEditScreen exposes mesExample (also fullscreen), card tags, creator and characterVersion. CharacterEditViewModel includes these fields in load, dirty state, draft payloads and both existing/new-card saves. CharacterCardMetadataEditor treats tags as metadata, preserves untouched imported entries, and only trims/deduplicates explicit additions. extensions is view/copy-only and remains the original string in drafts and exports.
- CharacterGreetingPolicy.choices uses position0 for the main greeting and original alternate index+1 for nonblank choices; empty alternates remain in stored cards. CharacterSessionService resolves a selected card ID/position/exact text against the freshly loaded card before creating anything. Home and Manage share CharacterGreetingPickerDialog with preview and main default; cancellation writes nothing. No selection retains the existing main-greeting path; conversation reset still uses its prior main-greeting policy.

- CharacterEditScreen generic fullscreen fields own system Back while visible: dismiss the transient editor before considering the card-level unsaved-changes exit guard. This includes newly exposed examples and alternate openings; unconfirmed text must never reach the card draft.

- Repository-writing card editor device regressions use the supported `-PCHATBAR_ISOLATED_ANDROID_TEST=true` build configuration; the default test ID is com.example.chatbar.instrumented, and the optional CHATBAR_ISOLATED_ANDROID_TEST_APP_ID must be a non-production com.example.chatbar.* ID. CharacterCardFieldsPersistenceTest makes explicit assumptions in an ordinary build, checks BuildConfig/runtime identity in an isolated build, and waits for app dependencies. See app/INSTRUMENTED_TESTS.md for reproducible commands; ordinary assumptions are not behavioral passes.

- Formal character save owns consumed-draft cleanup. The editor waits for a document confirmation to publish its draft file before allowing Save. Resume autosave after a rejected save, while retaining the restored draft’s original source fingerprint. Delete consumed draft records successfully before reclaiming their assets; pending cleanup retries on the already-saved card. Dirty comparison ignores derived document indexing fields and retains actual unconfirmed person or document edits in the draft. CharacterDraftSaveLifecycleTest covers conflict retry, cold reads, resource retention and confirmation ordering using the isolated build and synthetic cards.
