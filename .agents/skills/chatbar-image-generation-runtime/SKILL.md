## Service Invariants

- Keep NovelAiImageService.generate as shared NovelAI HTTP owner for chat, character images, prompt tool, and Moments.
- A session “网页版” image model changes only `NovelAiPromptDesigner` text transport through `StreamingChatService`; NovelAI byte generation remains here. Use `chatbar-web-ai-runtime` for WebView binding/DOM failures.
- `NovelAiImageService.generate` accepts explicit `NovelAiGenerationSettings`; serialize model, dimensions, 1–4 `n_samples`, steps, guidance, CFG Rescale, sampler, and base seed. Compatibility overloads default to V4.5 Full with CFG Rescale disabled. Chat and Moments resolve `ChatSession.novelAiImageModel` > `CharacterCard.defaultNovelAiImageModel` > global `AppSettings.novelAiImageModel`; other non-studio flows keep the global model. Non-studio flows retain legacy 28 steps, guidance 8, CFG Rescale 0, Euler Ancestral, and existing batch count. Studio persists `followDefaultNovelAiImageModel`: false preserves its explicit `selectedModel`; true resolves imported character-card default then global and caches the effective model in `selectedModel`. Missing flag on legacy drafts defaults false; only a newly created draft starts in follow mode.
- Emit intermediate, final, and error events consistently; cancel active OkHttp call when Flow closes.
- Treat `retry` stream frames as transient server control signals: keep reading the same stream instead of failing or starting another HTTP attempt.
- Treat a batch as successful only after the stream returns exactly the requested number of final frames. Surface partial or extra results as failure instead of silently accepting them.
- Retry HTTP 429 at the shared service only. Current contract is three total attempts, Retry-After capped at 30 seconds, otherwise 1-second then 2-second delay.
- Do not stack caller retries on top of service retries.
- Preserve correlation IDs and concrete HTTP/stream parse errors.
- Keep V4/V5 coordinates disabled unless product behavior explicitly changes; stored centers remain compatibility metadata.
- For V5 only, request construction collects quoted positive text from base and character prompts and appends one base `Text:` block. Preserve quoted source text; any explicit case-insensitive `Text:` block disables automation for the whole request. V4.5 remains unchanged.
- Studio token budgets count the same effective outbound prompt: V4.5 uses NovelAI T5 rules with a 512-token linked-field limit; V5 Full uses NovelAI Qwen rules with a 1471-token linked-field limit. Keep tokenizer assets lazy, compact, local, and off the main thread. Qwen's regex already carries explicit Unicode properties; do not pass Java `UNICODE_CHARACTER_CLASS`, which Android rejects on supported devices. Positive and negative totals each link base plus ordered character fields; counting failure stays visible but never blocks generation.
- Prompt Chinese annotations use an independent, non-interactive Canvas overlay anchored to raw `TextLayoutResult`; never insert annotation characters through `OutputTransformation`. Prompt-only line spacing reserves a compact ruby row below each source Tag; a 1px rule extends short Chinese labels to their source Tag end, and overlay scroll follows the raw field. When one source Tag spans several layout lines, consume and draw its Chinese translation across the corresponding ruby slots instead of ellipsizing it on the first line. Tag wrapping may use one stable same-length `OutputTransformation`: visually replace internal ASCII spaces outside natural-language/`Text:` blocks with NBSP, and replace ASCII commas with horizontally compressed fullwidth commas so Android exposes a real comma break opportunity. Raw spaces/commas and identity cursor offsets remain unchanged. Keep source text as sole owner for editing, selection/IME, clipboard, tokens, draft/history, undo/redo, and NovelAI requests. External whole-field replacements such as AI reply application must reset the field's internal editing state; selection-only callbacks must never rewrite draft text. Discard stale annotations whose saved source range no longer matches current text. Translation defaults off and is controlled by the persisted translate icon beside the Prompt section title; gray means off, primary tint means on, and off cancels work plus clears all annotations. `FullscreenTextEditor` remains raw-source-only. When enabled, show local dictionary results immediately, then batch-query shared `DanbooruTagCatalog` for exact Tag matches with every whitespace run normalized to `_`; only an exact catalog name with a reliable Chinese name replaces local display. Tag parsing treats `,` and `，` as equivalent delimiters outside quoted/Text blocks. Missing matches, natural-language segments, and catalog failures use bundled 12k-entry offline dictionary plus image-prompt overrides. Unknown proper names remain visibly separated in English. Annotation behavior is independent of the AI-design conversation page, and failures remain non-blocking.
- Studio reads current Anlas and V5 Opus allowance from `/user/subscription` on entry and after successful generation. Keep the V5 count explicitly approximate. Immediately subtract successful Anlas cost and allowance generations locally, then reconcile both against later server changes so a stale response cannot undo visible spending. Estimate button cost locally with the official pixel-plus-Steps formula and free-sample rules so setting changes stay immediate; Opus exemption requires one eligible text-to-image or Focused Inpainting sample, no active Precise/Vibe reference, and no batch. Image2Image remains charged. Focused Inpainting pricing uses its approximately one-megapixel request crop rather than full source dimensions. Account-fetch failure must not block generation or claim a V5-free request.
- Keep NovelAI quality-tag injection disabled and use `ucPreset=3` (None) so NovelAI does not combine its UC preset with app text. Send exactly one negative source—`NovelAiPromptPlan.effectiveNegativePrompt`—identically through legacy and V4 fields.
- Studio guidance is explicit request data: i2i uses `img2img`; Focused Inpainting keeps server action `infill`, the model-specific `-inpainting` ID, and `add_original_image=false`. Persist one explicit normalized focus rectangle plus Minimum Context (32–96px, default 96); the selected source area is capped at 589,824 pixels. Crop exactly that rectangle, then scale it toward 1,048,576 request pixels with dimensions floored to multiples of 64. The context border lies inside the focus rectangle and is excluded from redraw. Crop the optional full-resolution editor mask to the focus rectangle, restrict it to the inner redraw area, resize it at latent resolution, threshold at 155, then expand and send an opaque full-request-resolution binary PNG (white redraw, black preserve). An empty mask means redraw the whole inner area. Send shared i2i `strength`/`noise` plus `inpaintImg2ImgStrength`; when inpaint strength differs from 1, also send nested `img2img.strength` and `img2img.color_correct=true`. Build the client blend mask from the latent binary mask using radius-4 dilation, 8× expansion, then two radius-20 blur passes. Use Lanczos3 for focus-patch request and result resizing. Scale the returned patch and blend mask back to the exact crop, clear the base under that mask, and add the masked generated patch with lighter composition. Restore server text metadata after composition. Never send preview-blue pixels. V5 pauses Precise/Vibe without deleting their V4.5 draft state. Precise and Vibe remain mutually exclusive on the wire; Fidelity maps to secondary strength as `1 - fidelity`. Before sending Precise Reference, scale the source to fit the nearest supported Large canvas (1024×1536, 1472×1472, or 1536×1024), center it, and pad with opaque black; never crop it or send arbitrary source dimensions.
- Vibe encoding happens only after Generate through `/ai/encode-vibe`. Cache by source SHA-256, model, and Information Extracted; slider movement invalidates the attached encoding but never calls the endpoint. Its OkHttp request is coroutine-cancellable, carries `x-correlation-id`, and cancellation closes the active call. V4.5 accepts up to 16 Vibes; the fifth and each later Vibe adds 2 Anlas per output. Prepared encodings, normalized strengths, and request arrays stay positionally aligned. Keep the oriented source PNG at its natural dimensions; Precise Reference large-canvas padding does not apply to Vibe.
- Guidance editor keeps mode tabs above the canvas, exposes explicit enabled/disabled source state plus replace/clear actions, uses standard undo/redo turn-arrow icons plus a labeled Done action, and gives every numeric property its own full-width slider row. Clip every transformed bitmap/canvas to the editor bounds so pinch zoom never covers controls. One gesture recognizer owns the canvas: one pointer draws with the selected tool, while two pointers exclusively pan/zoom and cancel the pending stroke. When Focus is selected with an existing rectangle, show eight semantic-color resize handles with 48dp touch targets; corner handles resize both axes and edge handles resize one axis, committing one undo step on release while enforcing image, context, 8px-grid, and area bounds. Creating or resizing a rectangle keeps Focus selected; switch to brush/eraser only through explicit user choice. Each mode keeps one chronological undo timeline across strokes, bitmap transforms, source enable/clear, reference type, and numeric parameters; coalesce one continuous slider drag into one step, and keep redo undoable. Each mode retains its own in-memory canvas, undo/redo, brush, zoom, and pan while switching tabs; Done materializes every edited mode, while Back discards them. Clearing an Inpaint mask also removes its persisted mask asset reference and focus rectangle, then returns to the Focus tool. Inpaint preview uses one fixed-alpha blue overlay with a binary, non-antialiased edge; never multiply color alpha and paint alpha.

## File and State Safety

- Save the new image and persist its metadata/path before deleting an old app-owned file.
- On generation or save failure, retain the old image and metadata.
- If any image in a batch fails to save or the owning repository update fails, delete only newly saved files from that attempt; do not persist a partial batch.
- Never delete unrelated or user-owned files.
- History batch deletion may delete only its ID-owned cache directory; ordered multi-select deletion may delete only validated selected files beneath that directory and must retain unselected images plus recipe metadata. Gallery copies are external and never deleted. Do not migrate or sweep legacy unindexed prompt-tool directories.
- Keep prompt-tool reference images as owned draft assets. Copy a replacement before deleting the previous asset; removal and ViewModel cleanup may delete only that owned draft path.
- Guidance assets live under `filesDir/images/studio-guidance`. Normalize static inputs to oriented PNG, reject animated GIF, and deep-copy output/history sources before draft publication. Startup cleanup retains current-draft, history-undo, and editor-checkpoint references; history deletion never owns guidance copies. Vibe cache files are separate from image orphan cleanup.
- Guidance editor checkpoints persist guidance parameters without feeding rendered canvas pixels back into the active editor. Canvas pixels become owned assets only on Done; explicit cancel clears the checkpoint. Orphan cleanup must include current draft, history undo, and active checkpoint before deleting guidance PNGs.
- Keep image-processing imports and results in the owned `filesDir/images/image-processing` work area. APNG disguise plus static/dynamic restoration all use `.png` filenames with `image/png`; `.apng` remains import/share compatibility only. Full-screen long-press and image-processing result sharing silently use `application/octet-stream` for legacy `.apng`, GIF signatures, or PNG files containing `acTL`; other images use their image MIME type. Failure/cancellation deletes only its current target and temporary output; background housekeeping may delete only stale `.tmp` files.
- Gallery-import editing reuses ImageMosaicEditor. Static sources use its current edited bitmap for APNG disguise. GIF and every APNG disable mosaic, rotation, metadata stripping, and ordinary completion so animation cannot be flattened silently. A structurally valid ChatBar disguise switches the primary action to restore; third-party APNG remains read-only and unsupported.
- APNG disguise uses a canonical PNG/APNG chunk order with CRC validation and continuous APNG sequence numbers. The fixed brand cover is the PNG default image and never an animation frame. Marker keyword `ChatBarApngDisguise` records format version, static/dynamic kind, and true-frame count; restoration requires both marker and canonical structure.
- Static disguise v1 animation contains one full-canvas true frame plus one transparent 1×1 OVER no-change sentinel at 100 ms each with infinite play. Continue recognizing/restoring experimental v2 heartbeat files, but generate only v1. GIF conversion writes full composed RGBA frames, preserves GIF delays, maps missing loop extension to one APNG play, raw infinite to infinite, and finite repeat count N to N+1 total APNG plays.
- Static restore promotes first true `fdAT` payload to ordinary PNG `IDAT`. Dynamic restore promotes first true frame to APNG default/animation frame, renumbers later chunks, removes cover and marker, and preserves true-frame pixels, alpha, timing, and play count. Never claim restoration of original JPEG/WebP/GIF bytes, compression, or metadata.
- For static inputs, ImageMosaicEditor can create a metadata-stripped copy without changing current visual content; an untouched source keeps encoded pixels, color/rendering data, format, and non-default EXIF orientation. Leave source untouched and route returned copy through shared preview/save/share actions.
- Preserve owning entity identity and non-image state: message alternatives/timeline data or Moment text/likes/time.
- Moments on-demand generation (text-only post → generate image) reuses `NovelAiPromptDesigner.designForMoment` for the prompt plan and `NovelAiImageService.generate` for bytes; both stream live (design text via `onDelta`, image progress via `Intermediate`). Persist the new path+metadata and only then remove any replaced file; never reach image state if the post becomes a placeholder. Run inside `AiBackgroundWorkManager` + `GlobalImageGenerationConcurrencyGate`.
- Keep text generation and independent image tasks from blocking each other unless they mutate the same owned image slot.
- Use `chatbar-background-work-runtime` when changing shared protection, notification, network-loss, or foreground-service lifecycle behavior.

## Workflow

1. Classify change as prompt design, HTTP service, metadata, file lifecycle, concurrency, or UI.
2. Trace one generated image from prompt plan through bytes, saved path, metadata, display, and regeneration.
3. Put shared behavior in domain/image or shared UI; keep entity-specific replacement in its ViewModel/repository.
4. Define cancellation and failure ownership before changing concurrency.
5. Add service, serialization, and replacement-order tests.

## Stop Conditions

- Do not embed feature policy in NovelAiImageService.
- Do not make UI state the only copy of regeneration metadata.
- Do not delete the old image before the replacement is durable.
